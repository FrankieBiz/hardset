# Hardset

A hypertrophy logger for intermediate lifters. Local-first, CloudKit-synced, no accounts.

Three things it is trying to be, in order: honest about what it knows, aware of the specific
machines you train on, and fast to log a set.

**Status: the app, the widget and the analysis layer build and run.** Sessions, sets, prefill from
history, the rest bar, recovery of an interrupted workout, personal records, a 50-movement seed
catalogue and a picker; plus the permanent muscle vocabulary, fractional sets-per-muscle-per-week
with coverage, per-machine load history, session history, onboarding and the guided tour. CI builds
the app and widget (Debug and Release) on a macOS runner, renders every screen, and drives the real
app in the Simulator through six lifter journeys and a light-mode pass.

**Still device-bound:** nothing has run on a physical iPhone, and no signed build has exercised
CloudKit sync, AlarmKit alarms, HealthKit, or a real StoreKit purchase. Those remain the gates in
`DEVICE-CHECKLIST.md` and `docs/OWNER-DEVICE-CHECKLIST.md`. On this Linux machine `xcodebuild`
cannot run at all, so the app and widget are compiled by CI rather than locally.

## Layout

```
Hardset.xcodeproj          generated by Tools/generate_project.py -- do not hand-edit
Hardset/                   app target
HardsetWidget/             widget extension (required: AlarmAttributes is an ActivityAttributes)
HardsetTests/              app-target smoke tests
HardsetUITests/            real-app journeys, screenshots and accessibility audit reports
Packages/HardsetKit/
  HardsetCore              Foundation-only, nonisolated. Engine + alarm metadata. Tests on host.
  HardsetAlarm             iOS-only. AlarmKit conformance + rest-timer controller.
  HardsetHealth            HealthKit reads and writes, behind an explicit opt-in.
  HardsetStore             GRDB/SQLiteData. Schema, migration, sync.
  HardsetUI                Tokens, set row, keypad, rest bar, session screen, picker, volume
                           report, per-machine chart, history, methodology disclosure.
  HardsetFeature           The composition root. Lives here, not in the app target, so it builds.
```

`HardsetCore` deliberately imports nothing but Foundation, which is why the suite runs on macOS.

## Running the tests

```bash
make check          # Linux: syntax, Core, Store, query plans, palette contrast
./test.sh           # full HardsetKit suite, with engine-dependent tests in separate processes
```

The Linux gate runs 379 Core tests in 44 suites and 367 Store tests in 33 suites. The macOS lane
compiles the app and widget, runs 148 snapshot/UI-logic tests, and drives the real app through its
UI journeys. The script's separate processes exist because SQLiteData's non-live `SyncEngine`
attaches an in-memory metadatabase at a fixed shared-cache path, and the task local that resets it
between constructions is `package`-scoped, so two engines in one process contend for the same
SQLite file.

## Regenerating the project

```bash
python3 Tools/generate_project.py
```

No Tuist, no XcodeGen. The `.pbxproj` is generated from a script so it stays reviewable in a diff.

## Three invariants, each with tests

1. **Duration is derived, never stored.** `SessionTimeline` holds two immutable instants; an open
   session's duration is `nil`, not "time since it began". No `duration` column exists.
2. **Rest is a date, never a countdown.** `RestTimerState` is an enum, so "both a deadline and a
   remainder" is unrepresentable rather than merely discouraged.
3. **The logger does no database work per render.** `PriorPerformanceSnapshot` is an immutable value
   with no database handle, built once at session start.

## Things that must not regress

- `HardsetSyncDelegate.syncEngine(_:accountChanged:)` must keep its explicit implementation.
  Deleting it silently re-enables SQLiteData's default, which erases local data on iCloud
  sign-out. See `DECISIONS.md` §1.
- The schema is permanent. Read `DECISIONS.md` §4 before touching `Migrations.swift`, and note that
  several of those rules are validated by nothing but `SchemaTests`.
- Concurrency changes must be checked with `swift build` or `swiftc -c`. `swiftc -typecheck` gives
  a false all-clear on isolation errors.
