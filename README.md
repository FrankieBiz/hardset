# Hardset

A hypertrophy logger for intermediate lifters. Local-first, CloudKit-synced, no accounts.

Three things it is trying to be, in order: honest about what it knows, aware of the specific
machines you train on, and fast to log a set.

**Status: the logger, the analysis layer and the planner work, and the app runs on iOS.**
Sessions, sets, prefill from history, the rest bar, recovery of an interrupted workout, personal
records, an 81-movement seed catalogue and a picker; the permanent muscle vocabulary, fractional
sets-per-muscle-per-week with coverage, per-machine load history, a session history screen and a
post-workout summary; and plans — arrangements of movements you already train, dealt across the days
you choose; and your own equipment — movements you define (optionally based on a curated one,
which carries its muscles across but never its citations), a machine library for reviewing what you
have named, machine-name suggestions that never merge two machines, and a per-machine readout of
what you press on each. 774 tests pass in the supported test script, plus app and simulator UI
coverage for the complete logging path.

**Device status:** a signed Release build of the app and widget was installed and launched on an
iPhone 18,3 running iOS 26.6 on 2026-08-25. That local-only build deliberately omitted CloudKit and
push entitlements. No AlarmKit alarm has yet been observed firing on hardware and no CloudKit sync
has happened, so those stories remain unverified. `DEVICE-CHECKLIST.md` is the gate — read it before
believing any claim about the rest timer.

## Layout

```
Hardset.xcodeproj          generated by Tools/generate_project.py -- do not hand-edit
Hardset/                   app target
HardsetWidget/             widget extension (required: AlarmAttributes is an ActivityAttributes)
HardsetTests/              app-target smoke tests
HardsetAppUITests/         simulator journeys and launch-performance coverage
Packages/HardsetKit/
  HardsetCore              Foundation-only, nonisolated. Engine + alarm metadata. Tests on host.
  HardsetAlarm             iOS-only. AlarmKit conformance + rest-timer controller.
  HardsetStore             GRDB/SQLiteData. Schema, migration, sync.
  HardsetUI                Tokens, set row, keypad, rest bar, session screen, picker, volume
                           report, per-machine chart, history, planner, methodology disclosure.
  HardsetFeature           The composition root. Lives here, not in the app target, so it builds.
```

`HardsetCore` deliberately imports nothing but Foundation, which is why the suite runs on macOS.

## Running the tests

```bash
./test.sh
```

774 tests in the latest verified run — 769 in the main run and five re-run one process each. One
further test is a deliberately disabled canary that cannot run off-device. The
script separates the
engine-dependent tests because
SQLiteData's
non-live `SyncEngine` attaches an in-memory metadatabase at a fixed shared-cache path, and the task
local that resets it between constructions is `package`-scoped, so two engines in one process
contend for the same SQLite file.

## Clone on another computer

```bash
git clone https://github.com/FrankieBiz/hardset.git
cd hardset
git switch feat/splits
```

Read `WINDOWS-HANDOFF.md` before continuing work from a second computer. Windows can clone, inspect,
edit and commit the repository, but it cannot compile, run, sign or submit this iOS app. Those gates
require a Mac with Xcode 26 or later. Keep LF line endings; `.gitattributes` enforces them for source
and Xcode project files.

## Three invariants, each with tests

1. **Duration is derived, never stored.** `SessionTimeline` holds two immutable instants; an open
   session's duration is `nil`, not "time since it began". No `duration` column exists.
2. **Rest is a date, never a countdown.** `RestTimerState` is an enum, so "both a deadline and a
   remainder" is unrepresentable rather than merely discouraged.
3. **The logger does no database work per render.** `PriorPerformanceSnapshot` is an immutable value
   with no database handle, built once at session start.

## Things that must not regress

- `HardsetSyncDelegate.syncEngine(_:accountChanged:)` must keep its explicit implementation.
  Deleting it silently re-enables SQLiteData's default, which erases local data on iCloud
  sign-out. See `DECISIONS.md` §1.
- The schema is permanent. Read `DECISIONS.md` §4 before touching `Migrations.swift`, and note that
  several of those rules are validated by nothing but `SchemaTests`.
- Concurrency changes must be checked with `swift build` or `swiftc -c`. `swiftc -typecheck` gives
  a false all-clear on isolation errors.
