## 1. What is Hardset?

Hardset is a single-purpose, local-first hypertrophy logger for intermediate and advanced lifters on iOS. It is CloudKit-synced, requires no accounts, and refuses to build social feeds or opaque "AI coaching" algorithms.

It exists to answer one question honestly, set after set:
***What did I actually do, on this machine, and what does that justify me doing next?***

### The Three Core Differentiators
1. **Calibrated Honesty**: The app states what it knows and what it does not. Estimated or attributed numbers carry visible certainty badges (`CertaintyBadge`). Missing data renders as *"unevaluated"* rather than an interpolated curve or fabricated baseline.
2. **Machine-Level Awareness**: Load history is keyed to `exerciseID × machineID`. A 100 kg leg press on a 45° Cybex sled is not the same as a 100 kg horizontal cable press. Hardset never silently copies load across distinct machines.
3. **Gym-Floor Craft & Zero-Latency Speed**: Designed for someone with an elevated heart rate standing at a machine. One tap to log, prefilled from historical snapshots, micro-adjusted via inline steppers matching the machine's pin/plate increments. Zero database queries on the UI render loop.

## 3. Non-Negotiable Invariants (Never Regress)

Every model modifying this codebase must uphold these five architectural invariants:

1. **Duration is Derived, Never Stored**:
   - `SessionTimeline` holds two immutable timestamps (`startedAt`, `endedAt`). An active session's duration is `nil`, never a ticking integer. There is no `duration` column in SQLite.
2. **Rest is an Absolute Date, Never a Countdown**:
   - `RestTimerState` is modeled as an immutable target deadline (`Date`). "Both a deadline and a remainder" is unrepresentable. Ticking timers break across app backgrounding, Focus modes, and device restarts; absolute target dates survive.
3. **Zero Database Work Per View Render**:
   - `PriorPerformanceSnapshot` is an immutable struct built once at session initialization. Set row rendering and keyboard typing do zero SQL queries or disk I/O.
4. **Permanent, Additive-Only Database Schema**:
   - SQLite tables follow strict rules: never drop tables, never alter column nullability or defaults, never rename columns (`DECISIONS.md` §4).
   - `HardsetSyncDelegate.syncEngine(_:accountChanged:)` must remain explicitly implemented to prevent SQLiteData from wiping local data during iCloud account transitions.
5. **Swift 6 Strict Concurrency**:
   - Compiled with `.swiftLanguageMode(.v6)` and `.enableUpcomingFeature("NonisolatedNonsendingByDefault")`.
   - Never bridge `Sendable` boundaries unsafely with `@unchecked Sendable` unless backed by a primary source decision.

## 4. Growth & Product Moats (Context for Model Reasoning)

When designing features, copy, or user flows, align with these strategic product levers:

- **Anti-Social Ethos**: Hardset refuses to build an in-app social feed, follower graphs, or influencer comments.
- **The "Hardset Ledger" (Viral Shareable Artifact)**: Instead of an internal feed, generate high-contrast, dark-mode visual cards ("Workout Receipts") stamped with machine identity and `CertaintyBadge: Verified Honest` for sharing to Instagram Stories, iMessage, and Reddit.
- **1-Click Strong & Hevy CSV Migration**: Enable lifters with years of historical data to import seamlessly. Imported sets without machine IDs are honestly stamped `Imported • Unevaluated Machine`.
- **Anatomical Volume Taxonomy**: 24 discrete muscle groups with fractional attribution (direct vs. secondary targets) based on biomechanical literature, avoiding 1:1 naive counting or dogmatic MEV/MRV limits.
- **Dignified Monetization**: Core logging and personal data are 100% free and exportable forever. Optional lifetime unlock ($19.99) for multi-gym profiles and deep heatmaps, undercutting predatory $35/month competitors.
