# Front-end rebuild, Phase 2: Component kit — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Restyle every kit component on the calibrated-iron tokens, keeping each public signature, and give each component an all-states catalogue or preview and a snapshot, so Phases 3 to 6 compose screens from a kit that has already been rendered and reviewed.

**Architecture:** Component bodies are rewritten in place on the new token names and the Phase 1 primitives (`MachinedModifier`, `KnurlPattern`, `hardsetText`, `Tokens.Motion`, `Tokens.Haptic`). States a render cannot reach (pressed, focused, opened) are drawn through internal "face" views and state seams that take the state as a plain parameter, and are reached only through public per-group catalogue views, because the snapshot target imports HardsetUI without `@testable` and cannot inject Reduce Motion. The two large shared files are split first so that tasks own disjoint files and can run in parallel.

**Tech Stack:** Swift 6.2 tools, Swift 6 language mode, `@MainActor` by default in HardsetUI, `NonisolatedNonsendingByDefault`, SwiftUI on iOS 26.1, Swift Testing for the snapshot suites, Python 3 for the contrast checker. No new dependencies, no resource bundle, no Metal.

**Spec:** `docs/superpowers/specs/2026-11-12-frontend-rebuild-design.md` (sections "Component kit", "Materials and depth", "Motion", "Haptics", "Verification", "Delivery").

**Component map:** `docs/superpowers/plans/2026-11-13-frontend-rebuild-phase-2-component-map.md`. It holds, per component, the verbatim init signature, call-site counts, states to preview, tokens to replace, behaviour and label strings that must survive, and the delta to the spec. Tasks cite it as "Map §2.x". The map describes the code at `09e967c`; after Task 1 moves code, find symbols by name. Where the map and this plan disagree, this plan wins.

## Global Constraints

- iOS 26.1 minimum, Swift 6 language mode with strict concurrency; HardsetUI is `@MainActor` by default and `NonisolatedNonsendingByDefault` is on. Do not write `@MainActor` on views; mark `nonisolated` only for a computed-`id` `Identifiable` struct or a pure helper (the `HardsetSegment` pattern).
- Phase 2 covers spec kit lines 461 to 468 only: the press style, primitives, honesty components, logger components and pickers. Screens (`SessionView`, `HistoryView`, `WorkoutReceiptView`, `VolumeReportView`, `MuscleHeatmapView`, `ProgressionChartView`, everything in HardsetFeature), onboarding, `ScaledPhoneFrame` and `TourFixtures` are Phases 3 to 6. Phase 2 changes how a component looks and which states it can show; Phases 4 to 6 change what it does.
- Every public init of an existing kit component stays byte-identical. The only permitted signature changes are the additive defaulted parameters and additive public symbols this plan names (`HardsetTag`, `hardsetArrival()`, `CertaintyLevel.init(_:)`, `hardsetText(_:weight:)`, `isLoading`, `initialName`, `onCancel`, `initialCategory`, and the public `*CatalogView` types named in Tasks 2 to 10). Every call site in HardsetUI, HardsetFeature, the widget and the tests must keep compiling untouched.
- Kit bodies use only the new token names (`canvas`, `steel`, `steelRaised`, `steelPressed`, `hairline`, `controlEdge`, `chalk`, `chalkDim`, `plateBlue*`, `plateGreen*`, `plateYellow*`, `plateRed*`, `warning*`). The old alias names stay defined until Phase 7 and must not appear in any file a Phase 2 task owns.
- No new colour, type, radius, spacing or motion token. A task that seems to need one stops and escalates, because the spec requires a `DESIGN.md` edit in the same change. The one permitted checker change is the knurl-blend contrast pairs in Task 11.
- Colours resolve only through `swatch(...)` in `DesignTokens.swift`: no `Color(...)`, `UIColor`, `.white`, `.black`. Colour providers stay `nonisolated` with `@Sendable` closures. No asset catalogue in HardsetUI.
- Only `transform` and `opacity` animate. Every animation goes through `Tokens.Motion.adaptive(_, reduceMotion:)` and every scale is gated on `!reduceMotion`. A message arrives with an insertion-only opacity transition on `Motion.reveal` and no animated transaction.
- Haptics are `Tokens.Haptic.*` through `.sensoryFeedback`, with today's triggers unchanged. The log tap plays `success` only; `clank` sequencing waits for Phases 4 and 5.
- Accessibility: every label string a component speaks today survives byte for byte (the real-app journeys match labels, not identifiers; no `accessibilityIdentifier` exists). Labels are matched byte for byte against the source text, typographic characters included: the source writes `machine’s` at `MachinePickerView.swift:114` with a literal U+2019 apostrophe (bytes E2 80 99), not a straight apostrophe and not a Swift `\u{2019}` escape. Copy each string from its source line, never retype it, and never "fix" the code to match a plan string. Targets are 44 pt, and 56 pt in the logger. Layout switches at accessibility sizes; qualifying words wrap and are never truncated. Saved logger values keep full contrast even when their actions are disabled. Increase Contrast, Reduce Motion, VoiceOver and Voice Control behaviour is preserved.
- System fonts only; every type role is a Dynamic Type text style. Roles with non-zero tracking (`display` and `hero` -2%, `readout` -1%, `caption` and `unit` +1%) are applied through `.hardsetText(role)`, and a weighted variant of such a role through `.hardsetText(role, weight:)` (R17); `.hardsetText(role).fontWeight(...)` and a static weighted font of a tracked role are not used.
- Commits are authored by `FrankieBiz <frankabisignano@gmail.com>` with no AI attribution and no co-author trailer; no diagrams in docs or comments. Commit per Conventions, Committing. Keep every existing comment, docstring and test unless the token it describes is being replaced, a task step explicitly rewrites it, or the code it documents is deleted by a task step.
- Linux cannot compile SwiftUI. The Linux gate is `hardset-check parse`, the grep gates below, `Tools/check_contrast.py`, the generator diff and `make check`. Snapshot tests assert nothing about pixels: they fail only when a view cannot be built. Never claim a render passed without having opened its PNG from the macOS artefact (`hardset-ios-ui`, workflow "iOS build and screens", triggered by pushing the branch).

## Review Focus

Failure modes the spec implies but the tasks' renders do not exercise by themselves. Each has an owning task whose steps pin it.

1. **Reduce Motion on.** No kit component animates or scales under Reduce Motion, yet a press still shows through a fill or opacity change. Pinned by the multi-line Reduce Motion grep gates in every task and by Task 2's routing of the button and key bodies through `adaptive`; the state itself is unrenderable and is checked by review. Button roles: primary, secondary, quiet and destructive each change fill, edge or opacity when pressed (R38). Check the pressed destructive sample in the existing token-catalogue buttons capture against its rest sample.
2. **Increase Contrast and the light appearance on certainty, banners and tags.** Certainty state is carried by word and symbol, not hue; the unevaluated capsule is carried only by its outline under Increase Contrast. Banner kind is carried by symbol (distinct per kind) and hue, plus the title when present; message-only banners rely on the message text, and spoken kind is unchanged in Phase 2 (R39). Pinned for certainty by Task 7's light-contrast and dark-contrast captures, and for banners and tags by Task 5's and Task 4's dark-contrast captures. The engine truth behind the badges is pinned by Task 7's `KitLogicTests` (reps 3, 8, 11, 12, 15, 25 on a 60 kg set, and the `Certainty` to `CertaintyLevel` mapping), and on Linux by Core's `StrengthMathTests`.
3. **Accessibility3 reflow.** "High confidence" and "Moderate confidence" wrap rather than truncate; the screen-header action moves above the title; the keypad quick steps become a two-by-two grid; segments and tags wrap; header circles stop growing at xxxLarge. Pinned by the ax3 captures in Tasks 3, 4, 5, 7, 9, 10, and for the picker error banners (pinned at ordinary sizes, moved into the scrolling content at accessibility sizes, R41) by the phone-height ax3 error captures in Tasks 13, 14 and 15.
4. **Frozen labels and set-row geometry.** The real-app journeys tap the set row at horizontal offsets 0.44, 0.93 and 0.08 and match label text by prefix. A restyle that shifts a column or rewords a label silently breaks `testWorkoutJourneyDark` and `testCorrectionsAndDiscardDark`. Pinned by the "Labels kept" gate in every task (literal strings by `rg -F` in their declaring file, composed labels by diff) and by Task 9's `SetRowMetrics`-unchanged check plus those two journeys green on CI.
5. **Saved and disabled states.** A saved set's values keep full foreground contrast even though their fields are inert; a disabled button dims to 0.4 but a disabled press-style control is never dimmed by the press style. Pinned by Task 2's disabled samples in the press section and Task 9's read-only row capture.
